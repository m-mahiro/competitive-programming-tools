# CP Toolkit の性能

CP Toolkit は、以前は別々の UserScript だった機能を1本にまとめたものです。統合前の UserScript 群と、同じ機能だけを ON にした CP Toolkit を、実際の Tampermonkey で同じ条件で動かして比べました。

## 1. 結果(1.0.26)

AtCoder の9ページを開いたときの、スクリプトなしの状態からの増分の合計です。小さいほど軽いことを表します。

| | 旧スクリプト 26本 | CP Toolkit(同じ機能) | 旧 nsubaru 版 8本 | CP Toolkit(同じ機能) |
|---|---:|---:|---:|---:|
| CPU 時間 | 514 ms | **432 ms**(-16%) | 214 ms | 416 ms(+94%) |
| メモリ(GC 後の JS ヒープ) | 7.68 MB | **7.08 MB**(-8%) | 3.60 MB | 5.66 MB(+57%) |
| 複数のスクリプトや機能が触った要素 | 310 | **82**(-74%) | 103 | 60(-42%) |
| 強制レイアウトの疑い | 7 | **0** | 6 | 0 |

- 旧スクリプトが多く動くページほど、統合の効果が大きくなります。問題文のページでは、CPU 時間が 140 ms から 66 ms に、メモリが 1.67 MB から 0.74 MB に減りました。Tampermonkey はスクリプト1本ごとに注入と GM API の準備をするので、本数が減るとその分が減ります。
- 旧スクリプトがほとんど動かないページ(トップ、ユーザー)では、CP Toolkit の方が重くなります。機能が動かないページでも、全機能のコードを読み込むためです。
- DOM への重複アクセスは大きく減りました。旧スクリプトでは、同じ要素を別々のスクリプトがそれぞれ探し直していました。
- 旧 nsubaru 版8本だけと比べると、CP Toolkit の方が重くなります。

ページごとの値、内訳、検定の結果は [1.0.26 の詳細](./bench/reports/1.0.26.md) にあります。

## 3. 測り方

- 旧スクリプトは、統合前の nsubaru 版8本の最終版と、[SOURCES.md](./SOURCES.md) で「派生」「模倣」の元になった公開スクリプト18本です。CP Toolkit は、旧スクリプトに対応する機能だけを ON にしました。
- Tampermonkey を入れた Chromium で、録画した AtCoder の公開ページ9つを開き、CPU プロファイル、GC 後の JS ヒープ、ページ全体の処理時間、放置時の CPU 時間を測りました。
- DOM への重複アクセスだけは、Tampermonkey の代わりの軽いシムで測りました。Tampermonkey のスクリプトはページとは別の実行環境で動き、ページ側から DOM API の呼び出しが見えないためです。
- 提出一覧・順位表・提出画面はログインが要るので対象外です。

手順、計測のコード、再現の方法は [bench/README.md](./bench/README.md) にあります。`bench/setup.sh` と `bench/run.sh` で、どの版でも同じように測れます。
